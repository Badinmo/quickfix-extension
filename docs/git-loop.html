Two-Laptop Git Loop

How to save your work to GitHub from one machine and pick it up on another, without the drag-and-drop uploads. Five commands, in the same order, every time.

Setting up a machine (once each)

Do this once per laptop. After that you only ever use the loop in the next section.

Tell git who you are

Every commit is stamped with a name and email. Git refuses to commit until you set them.

git config --global user.name "Mothanna Albadin"
git config --global user.email "mothanna.alb@gmail.com"

On a machine that doesn't have the project yet

Downloads the whole project and its history into a new folder. Run it from wherever you keep your projects — it creates the folder for you. 

git clone https://github.com/YOUR-USERNAME/quickfix-extension.git

On this work laptop, where the folder already exists

This folder isn't a git repo yet — it was uploaded by hand. These commands adopt the GitHub history without touching your files, so nothing local is lost. 

cd "C:\Users\motha\Projects\Extensions\New folder\quickfix-extension\quickfix-extension"
git init
git branch -M main
git remote add origin https://github.com/YOUR-USERNAME/quickfix-extension.git
git fetch origin
git reset origin/main
Copy the folder first

Before running that block, make a duplicate of the folder somewhere safe. The commands above are non-destructive, but a typo in one of them might not be — and this folder is what your browser loads the extension from.

The loop

This is the whole thing. Same five steps, same order, every session — on either machine.

  1. Pull — get what the other laptop did

    Always first, before you change anything. Skipping this is what causes the mess in the last section.

    git pull
  2. Work — edit files normally

    Nothing git-related here. Edit, test, reload the extension — however long that takes.

  3. Check — see what you changed

    Lists every file you touched. Worth a look each time, so nothing sneaks into a commit.

    git status
  4. Commit — save a labelled snapshot

    add -A stages every change; -m is the label. This saves locally only — GitHub doesn't see it yet. 

    git add -A
git commit -m "Fix false 'text changed' error on multi-paragraph selections"
  5. Push — send it to GitHub

    Now the other laptop can pull it. The very first push from a machine needs -u origin main; after that plain git push is enough. 

    git push
The rule that keeps two laptops sane

Pull when you sit down. Push before you walk away. Git can't sync what you never pushed — if you leave work uncommitted on the work laptop and then edit the same file at home, you get to untangle it by hand later.

Naming a commit

The message is for future-you, scrolling a list months from now trying to find when something broke. Say what changed, in the imperative — "Fix", "Add", "Remove" — as though finishing the sentence "this commit will…".

✓Update model list to Gemini 3, drop retired 2.5 models
✓Raise token budget so thinking doesn't consume the whole reply
✓Add regression test for multi-paragraph selections
✕update
✕fixed stuff
✕asdf

Keep it under about 70 characters. If you genuinely need to explain why, commit without -m — git opens an editor where line 1 is the title, then a blank line, then as much detail as you like.

When git complains

Four messages cover almost everything you'll hit on a solo two-machine repo.

It saysIt meansDo this
Updates were rejected… non-fast-forward The other laptop pushed something you don't have yet. Run git pull, then git push again.
Please tell me who you are Identity not set on this machine. Run the two git config commands at the top.
CONFLICT (content): Merge conflict in… You changed the same lines on both laptops. Open the file. Git marks both versions with <<<<<<< and >>>>>>> — delete the markers and the version you don't want, then git add -A and git commit.
A browser window asking you to sign in to GitHub First push from this machine — it's authenticating you. Sign in. It's remembered from then on.
Two commands worth knowing

git log --oneline — the list of commits, newest first. This is what your commit names buy you.

git diff — exactly what you've changed since the last commit, line by line. Press q to get out of it.
